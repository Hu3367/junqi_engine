我说的“专家模型”，不是最终要部署的神经网络，而是一个能够稳定执行棋理、搜索局面、产生高质量决策与标签的 Teacher / Oracle。

对于你这个军棋翻棋项目，我不建议：

棋理体系 → 直接预训练 → RL

而更建议：

棋理体系
   ↓
专家模型 V0
   ↓
专家数据集
   ↓
监督预训练 / 棋理预训练
   ↓
专家模型自博弈增强
   ↓
RL / 自博弈
   ↓
最终模型
1. 为什么一定要先做专家模型？

你目前遇到的核心问题是：

“棋子明明摆在面前，AI 甚至不会正常吃子。”

这说明当前最缺的并不是模型容量，而是基本棋理还没有进入训练目标。

假设你直接预训练：

输入：棋盘
输出：下一步

而你的训练数据本身又来自一个水平不高的 AI，那么实际上是在训练：

低水平 AI → 更像低水平 AI

这很容易产生一个非常危险的循环。

2. 专家模型首先承担的是“老师”角色

棋理体系完成后，你应该先把它程序化。

例如：

局面 S
   ↓
棋理分析器
   ├─ 是否存在立即吃子？
   ├─ 是否存在强制吃子？
   ├─ 当前威胁是什么？
   ├─ 当前主动权属于谁？
   ├─ 哪些格子是关键节点？
   ├─ 哪个暗子的概率最高？
   ├─ 当前应该攻击/防守/兑子？
   └─ 当前战略计划是什么？

然后专家搜索器进一步回答：

动作 A
动作 B
动作 C
   ↓
经过 N 层搜索
   ↓
哪个结果最好？

于是你就能获得：

state
policy
value
tactical labels
strategic labels

这才是非常有价值的训练数据。

3. 而且你的“专家模型”最好不是一步到位的

我建议你把专家模型拆成 4 个层级。

Expert-0：规则专家

先保证：

100% 正确识别合法走法
100% 正确识别攻击关系
100% 正确处理翻棋
100% 正确处理工兵/炸弹/地雷

这个其实比神经网络重要得多。

Expert-1：战术专家

这一层只解决：

“棋盘上现在有什么立即发生的事情？”

例如：

能不能吃？
吃哪个？
会不会被反吃？
有没有连续吃？
有没有必杀？
有没有直接威胁军旗？

甚至可以建立一批专门的 tactical puzzles：

Puzzle 001:
白方有 3 个候选动作
其中只有 1 个能够盈利

Puzzle 002:
有吃子机会
但吃子会导致军长被炸

Puzzle 003:
看到敌方司令
但真正正确的是先走工兵

这个阶段的目标甚至不应该是“赢棋”。

而应该是：

让模型首先学会基本战术语言。

4. Expert-2：棋理专家

这是你现在最需要打造的一层。

它开始真正执行前面说的棋理体系：

Information
Space
Tempo
Threat
Material
Initiative
Fortress
Flag Pressure
Plan

例如同样有一个吃子：

A：吃掉敌方团长
B：不吃，抢一个关键行营

传统 MVV-LVA 很可能认为：

A > B

但棋理专家可能判断：

A：
+45 material
-20 tempo
-40 flag safety
-30 mobility

B：
+0 material
+35 space
+30 tempo
+50 flag pressure

最后：

B > A

这才是真正意义上的“棋理”。

5. Expert-3：搜索专家

最后才让搜索承担：

“如果我这样做，未来会发生什么？”

这一层可以逐步加入你现在已有的：

PIMC

MCTS

Beam Search

Alpha-Beta 类搜索

imperfect-information sampling

但注意：

搜索不应该负责发明棋理。

更理想的关系是：

棋理 → 候选动作
搜索 → 验证候选动作

而不是：

搜索 → 自己猜棋理
6. 专家模型完成以后，再做预训练

这时候你的“预训练”就非常不一样了。

不再只是：

局面 → 下一步

而可以做多任务训练：

Input
 ↓
┌─────────────────────────┐
│        Game State        │
└─────────────────────────┘
 ↓
 ├── Policy
 ├── Value
 ├── Tactical Result
 ├── Threat
 ├── Initiative
 ├── Space Control
 ├── Flag Pressure
 ├── Information State
 └── Strategic Plan

也就是说，一个模型同时学习：

“怎么走” + “为什么这样走”。

这对你的项目非常重要。

7. 我甚至建议你不要一开始就拿大量完整对局做预训练

因为完整对局的数据有一个问题：

大量局面其实信息量很低。

例如：

双方在走等待手

这种数据大量堆进去，对模型学习基本棋理帮助并不大。

↓

这比直接喂 100 万局完整棋谱更有价值。

8. 你可以把它理解成“老师先出题”

整个工程实际上可以设计成：

             棋理体系
                 ↓
         ┌──────────────┐
         │ Expert Engine│
         └──────┬───────┘
                ↓
        自动生成训练题
                ↓
 ┌──────────────────────────┐
 │ Tactical Dataset         │
 │ Strategic Dataset        │
 │ Endgame Dataset          │
 │ Imperfect Info Dataset   │
 └───────────┬──────────────┘
             ↓
          Pretrain
             ↓
        Student Model
             ↓
      Self-play / RL
             ↓
        Stronger Model
             ↓
          反哺 Expert

这就变成一个Teacher → Student → Self-play → Teacher增强的循环。

9. 还有一个关键点：专家模型不用一开始就很强

这点特别重要。

你可能会产生一个担心：

“我自己的专家模型都打不过高手，那拿它训练出来的模型不是也只能这么强？”

实际上不完全是这样。

专家模型只需要做到：

第一阶段

棋理正确

而不一定：

棋力顶尖

例如：

专家模型 V0

吃子识别        99%
合法走法        100%
基础战术         95%
明显威胁识别     90%
战略判断         70%
复杂残局         50%

已经足以产生第一批高质量训练数据。

然后：

Expert V0
 ↓
Pretrain
 ↓
Model V1
 ↓
Self-play
 ↓
发现专家漏洞
 ↓
Expert V1
 ↓
Pretrain / RL

慢慢进化。

10. 对你目前项目，我反而不建议立即上大规模 RL

因为你现在的状态明显还处于：

如果现在直接：

12. 最关键的一句话

你现在不要把：

“专家模型”和“预训练”

理解成二选一。

它们其实是上下游关系：

专家模型负责制造“正确棋理”；预训练负责把这些棋理压缩进神经网络；自博弈负责突破专家模型原有的上限。

因此你的下一阶段最合理的顺序是：

棋理体系 → 专家模型 → 棋理数据集 → 预训练 → 自博弈 → RL。

而且结合你前面提到的 4080S 本地条件，这个路线比“直接训练一个大型模型”现实得多。尤其第一阶段的 Expert Engine 和数据生成，完全可以主要依靠 CPU + 搜索完成，4080S 留给后面的神经网络训练会更合理。

你目前真正值得花大量精力的，其实是 Expert Engine V0 的设计——一旦这一层设计正确，后面的“预训练数据怎么生成、模型输入输出怎么设计、课程学习怎么安排、RL 怎么接”都会顺很多。
