## 1. 基础规则定义

### 1.1 棋盘几何结构

**标准规格**: 12 行 × 5 列 = 60 格（每方 25 子，共 50 子）

```python
# junqi/rules.py lines 18-98

# 行营（安全区，开局不放子）- 共 10 个
CAMPS = frozenset({
    (2, 1), (2, 3), (3, 2), (4, 1), (4, 3),      # 上方 5 个
    (7, 1), (7, 3), (8, 2), (9, 1), (9, 3),      # 下方 5 个
})

# 大本营（进入后不能再动）- 共 4 个
HQS = frozenset({(0, 1), (0, 3), (11, 1), (11, 3)})

# 铁路网布局
RAIL_ROWS = frozenset({1, 5, 6, 10})   # 横向铁路
RAIL_COLS = frozenset({0, 4})          # 纵向铁路（贯通全场）

# 前线山界通道阻断（col1/col3 无桥阻断，col0/col2/col4 为三座铁桥贯通全场）
CROSS_BLOCKED = frozenset({
    frozenset(((5, 1), (6, 1))),
    frozenset(((5, 3), (6, 3))),
})
```

**关键特性**:
- 行营内棋子**不可被攻击**（绝对安全区）
- 大本营进入后**不能再移动**（翻棋模式默认可解锁）
- 铁路可长距离滑行（工兵可任意转弯飞行）
- 前线三座铁桥（左桥 col0、中桥 col2、右桥 col4）铁路完全相通；col1/col3 山界阻断必须绕行中桥或两侧铁桥

### 1.3 战斗结算规则

```python
# junqi/rules.py lines 171-182
def battle(attacker: Rank, defender: Rank) -> str:
    """返回战斗结果：'attacker_wins' | 'defender_wins' | 'both_die'"""
    
    if defender == Rank.QI:
        return ATTACKER_WINS          # 扛旗成功
    
    if attacker == Rank.ZHA or defender == Rank.ZHA:
        return BOTH_DIE              # 炸弹遇任何子同归于尽
    
    if defender == Rank.LEI:
        return ATTACKER_WINS if attacker == Rank.GONG else DEFENDER_WINS
                                    # 工兵挖雷成功，其他棋子攻击雷失败
    
    if attacker == defender:
        return BOTH_DIE              # 同等级的子相遇同归于尽
    
    return ATTACKER_WINS if attacker > defender else DEFENDER_WINS
                                      # 高等级吃低等级
```

### 1.5 走法合法性判定

**关键条件** (`junqi/state.py` lines 157-174):

1. ❌ **不可攻击暗子** - 必须翻开后才能成为目标
2. ❌ **不可攻击行营内棋子** - 行营是安全区
3. ❌ **禁止自杀式攻击** - 小子撞大子被禁止
4. ✅ **军旗特殊规则** - 只有工兵能吃（若开启 `flag_gong_only`），且需满足地雷清除条件
5. ✅ **大本营锁死** - 当 `hq_locks_pieces=True` 时不可动（翻棋模式为 false）

```python
# 伪代码示例
def _attackable(self, attacker, target, tpos, hidden, flag_ok):
    if not target.revealed:       # 不可攻击暗子
        return False
    if is_camp(tpos):             # 不可攻击行营内棋子
        return False
    if target.rank == Rank.QI:
        if not flag_ok:           # 未满足扛旗条件
            return False
        if self.cfg.flag_gong_only and attacker != Rank.GONG:
            return False          # 非工兵不能吃军旗
    if not self.cfg.allow_suicide_attack:
        if battle(attacker, target.rank) == "defender_wins":
            return False          # 小子不可撞大子
    return True
```

#### 首翻定色与实战应对定式

1. **首翻出大子 (司令/军长/师长)**:
   - **执红定色成功**：切忌盲目出击！大子首翻极易成为对方暗子“撞炸弹”的靶子。应第一时间利用公路移入行营（如 `(8,2)` 或 `(7,1)`），建立中央安全灯塔。
2. **首翻出炸弹**:
   - 保持静止，隐藏威胁。对方未知炸弹存在前，不可过早移动，迫使对方在周边翻棋时心存忌惮。
3. **首翻出工兵**:
   - 第一时间寻机驶入铁路，建立全场巡航威慑。
4. **首翻出军旗**:
   - 劣势开局！军旗暴露会立即引来敌方工兵与大军的长期战术锁定，己方必须以该兵站为核心迅速构建防御阵地。

#### 优先翻棋原则

**战术要点**:
1. **先翻前线** - Row 5 和 Row 6 的棋子具有最大机动价值
2. **避免暴露大子** - 司令、军长等大子在暗子阶段不要过早翻开
3. **侦察优先** - 优先翻开可能位于边路的中小子，获取信息而不损失太多时差

**翻棋安全性评分** (`junqi/search.py` lines 122-150):

```python
                elif nb.rank not in (Rank.LEI, Rank.QI):
                    enemy_threats += 1
    
    if friendly_guards > enemy_threats:
        safety_score = 60_000.0 + (friendly_guards - enemy_threats) * 5000.0

        safety_score = 500.0 - enemy_threats * 1000.0
```

#### 开局翻棋顺序与“据点辐射拓荒”定式 ⭐⭐⭐⭐⭐

**底层客观规律：开局全随机性**
在翻棋开局阶段，全盘 50 颗暗子完全洗乱随机分布，任何一方在翻开前均**无法预知翻出的是己方还是敌方、是大子还是小子**。因此，任何试图“预先挑排长进营”的假想都是脱离实际的。

实战中高水平棋手遵循的核心定式为：**首翻子力据点化，依托行营辐射拓荒（Strongpoint & Camp-Radiating Exploitation）**：

1. **以首翻己方子力为据点**：
   无论翻出的第一个己方子力是何军阶（哪怕是军长、师长甚至司令），该棋子立即作为初始**核心据点（Foothold）**，迅速抢占相邻的四角行营或站稳咽喉；
2. **据点大子的辐射翻棋主动权（以据点军长翻 1、2、3 号相邻暗位为例）**：
   依托据点大子向周围相邻暗子（如上方 1、右方 2、斜角 3）进行辐射式翻棋，无论翻出何种结果，均牢牢占据博弈主动权：
   - **情景 A：翻出敌方子力**：由于据点是大子（如军长），除司令/炸弹外全场直接压制。由于刚翻开的敌子处于时差激活态无法动弹，据点大子下回合可直接起步吃子，稳赚战果；
   - **情景 B：翻出敌方炸弹**：敌方炸弹虽具威胁，但刚翻开不可移动。**据点大子坚决不动**（不主动撞炸），主动权仍在己方手中。己方可继续翻开炸弹周边的其他暗位，赌概率翻出己方小子就地扑出拆弹；
   - **情景 C：翻出己方子力（行营接力连锁扩圈）**：翻出己方子力后，该新子力可在下回合顺势移入相邻的“B 行营”。新子力进驻 B 行营不仅自身获得绝对安全免受攻击，还将己方的翻棋与侦察辐射网络再次成倍外扩，形成“双星据点”或“多营联动”的绝对控盘态势！

### 2.2 行营争夺的重要性（1000 局官方实战大数据实证）

**大数据实证揭示真实开局形态**：
对 1000 局官方复盘的前 20 手微观数据挖掘，彻底印证了“据点占营、营周拓荒”是翻棋开局的第一支配法则：

1. **走子即进营（82.7% 进营率）**：
   在前 20 手出现的全部 8,503 次移动中，**高达 82.7%（7,035 次）是棋子进入行营（Into Camp）**！几乎所有初始走子都以抢占行营为第一目的。
2. **翻棋紧贴行营（96.2% 邻营翻棋）**：
   在前 20 手产生的全部 10,615 次翻棋中，**高达 96.2%（10,209 次）直接发生在行营相邻格**！这无可辩驳地证实了人类棋手均严格围绕行营据点展开辐射翻棋。
3. **进营军阶全随机（破除刻意挑小子进营误区）**：
   前 20 手进营棋子涵盖所有 10 种军阶：排长 14.1%、工兵 13.8%、连长 13.7%、旅长 10.4%、团长 10.4%、营长 10.3%、师长 9.2%、炸弹 8.8%、军长 4.9%、司令 4.4%。各兵种进营比例与其在 25 枚棋子中的自然生成概率完全一致，实证确认“翻到何子何子即据点”。
4. **行营单向打击特权与被翻子力战术瘫痪（50.1% 开局吃子源于出营扑杀）⭐⭐⭐⭐⭐**：
   实战中常说的“翻棋多胜率高”，**绝非指机械的翻棋动作次数多，而是指“翻出己方棋子更多、占据行营更多”的一方拥有压倒性主动权**！
   - **单向攻防不对称性**：行营享有绝对免战保护，任何外部棋子不可攻击行营；但行营内的棋子却拥有随时“走出行营扑杀周边”的主动攻击权；
   - **被翻出敌子的战术瘫痪态**：当在行营周围翻出敌方棋子时，该敌子处于绝对被动死锁——刚翻开当回合无法移动；到了下回合哪怕轮到敌方行动，也**因规则铁律绝不能攻击行营内的子**！若该敌子军阶低于行营子力，留在原地即成活靶，冒然移出也会被行营子力追杀；
   - **50.1% 开局吃子实证**：大数据统计显示，在 1000 局前 20 手发生的全部 768 次吃子交火中，**整整 385 次（50.1%）是由行营内棋子直接出营扑杀发起的**！占据行营的一方等于手握单向开火的炮台，将敌方刚翻开的棋子直接锁死在兵站内。

### 2.4 两回合时差利用

**核心原理**: 
- 翻开一个暗子需要 1 回合
- 该暗子变成明子后可走棋需要另外 1 回合
- **总计 2 回合才能激活一个新棋子**

**战术利用**:
```
情境：我有明子 A，对手有暗子 B

第 1 回合：我用 A 吃掉对手的 C
第 2 回合：对手翻转 B（不能走）  
第 3 回合：对手才能用 B 行动

我的优势：
- 第 1 回合我完成了一次有效行动（吃子）
- 对手在第 2 回合浪费了翻棋的机会成本
```

**最优策略**:
1. **保持明子数量优势** - 尽可能多地保持活跃明子
2. **利用时差发动攻击** - 当对手频繁翻棋时，抓紧时机扩大优势
3. **避免被动翻棋** - 除非必要，不要让自己陷入纯翻棋的困境

**子力差精确计算** (`junqi/analysis.py` lines 53-84):

```python
def material_diff(state: GameState, seat: int) -> float:
    """己方存活子力 − 对方存活子力，归一化到 [-1.0, 1.0]"""
    my_color = state.my_color(seat)
    opp_color = other(my_color)
    
    my_mat = 0.0
    opp_mat = 0.0
    
    # 1. 棋盘明子价值
    for pc in state.board.values():
        if pc.revealed:
            v = PIECE_VALUES.get(pc.rank, 0.0)
            if pc.color == my_color:
                my_mat += v
            elif pc.color == opp_color:
                opp_mat += v
    
    # 2. 暗子池期望（剩余池 = 总构成 − 明子 − 阵亡）
    rem = state.remaining_types()
    for (clr, rk), count in rem.items():
        v = count * PIECE_VALUES.get(rk, 0.0)
        if clr == my_color:
            my_mat += v
        elif clr == opp_color:
            opp_mat += v
    
    diff = (my_mat - opp_mat) / MATERIAL_MAX
    return max(-1.0, min(1.0, float(diff)))
```

#### 棋理修正：为什么近 47% 的炸弹被中小子（连/排/团/营）碰掉？

在过去的部分主观论调中，有人误以为是“用炸弹战术性去清暗棋”或“暗探走步误触踩炸”。**但必须明确翻棋的铁律：翻棋模式中无法攻击未翻开的暗棋**！

那么实战中连长、排长、团长碰掉炸弹的高频现象究竟从何而来？其实战本质是极其经典的**“小子占营摸奖，贴身拆弹”定式（Camp-Adjacent Low-Piece Bomb Disposal）**：

1. **行营绝对安全与翻棋辐射**：
   实战开中盘，高水平棋手会积极用廉价小子（排长 18分、连长 25分、工兵 42分）进驻行营。行营内棋子免受攻击，是极佳的掩体与侦察跳板。
2. **摸奖翻出敌方炸弹**：
   行营内的小子翻开相邻兵站的暗子（或敌方翻开该暗子），结果暴露为敌方炸弹。
3. **两回合时差与瘫痪状态**：
   根据翻棋规则，**暗子被翻开的当回合处于“被激活”过程，不可立即移动**！此时敌方炸弹处于暴露但无法机动的无防御状态。
4. **低成本就地拆弹（主动扑撞同归于尽）**：
   如果任由敌方炸弹在下一回合启动，它将对己方司令、军长构成致命核威慑。因此，**行营内早已就绪的廉价小子（排/连/工）在轮到行动时，会毫不犹豫地主动出营撞向这颗炸弹，同归于尽**！
   - **交换比极其划算**：用 18 分的小排长换掉敌方全盘仅有的 2 颗战略核武之一（52 分），净赚 34 分物质分，更彻底解除了敌方炸弹对我方大子的长期牵制。
   - 对炸弹方而言，炸弹翻在敌方控阵的小子身边属于“翻出即遭封杀”，根本无法逃脱被廉价子力兑掉的宿命。
5. **工兵斩首价值**：
   用炸弹击杀对方工兵虽然分值上看似“亏损 10 分”，但直接废除对方清除地雷与扛旗的期权，在实战中经常直接为己方筑起不可破防的“铁桶阵”甚至逼和逆转。

### 3.4 司令战损与“梯队接管”定理（颠覆单司令决定论！）⭐⭐⭐⭐⭐

#### 1000 局大数据实证：
- **有效对局样本**：261 局明确分出司令战死先后；
- **先死司令方最终落败**：130 局（**49.8%**）；
- **先死司令方逆转获胜**：131 局（**50.2%**）；
- **实证结论**：**先死司令方胜负完全对半开！**

#### 棋理体系修正：“梯队接管法则”
1. **司令牺牲往往伴随巨大代价**：对方为了吃掉我方司令，往往需要付出己方炸弹、或者司令暴露遭到我方伏击、或者主力大军离开防区；
2. **次级梯队（军长、双师长）的即时接管**：只要己方军长、师长健全，当对方司令因吃我方司令而暴露在明处时，对方已无绝对王牌。己方次级大军配合双炸弹，反而能建立全盘反围剿火力网；
3. **AI 估值修正警告**：传统 AI 常在司令战死瞬间将胜率断崖式下调至 -0.8 ~ -1.0，导致出现自暴自弃走法。根据实战大数据，**单司令死亡的价值惩罚必须收窄，应综合计算双方二线大子（军/师/旅）净差与炸弹存活数**。

### 4.3 典型实战和棋定式库（301 局和棋特征提炼）

在 301 局和棋中，官方原因码 40（协议求和）占 88%（265 局），限步和棋占 10%（31 局）：

#### 定式 1: 双无工兵绝对死和定式
- **格局**：双方军旗均深藏在地雷阵后（或行营后），而**全盘工兵已全部阵亡**；
- **棋理**：没有工兵就无法排雷，任何大子撞雷必死，军旗永不可达。此时继续行棋毫无意义，双方必定协议求和。

#### 定式 2: 行营避险死守求和定式
- **格局**：一方大子（如单军长）落入下风，但成功占据中央安全行营（如 `(3,2)` 或 `(8,2)`）；
- **棋理**：对方虽有微弱子力优势，但行营内棋子绝对免疫攻击，大子一旦出营即被围剿，双方形成“你进不来、我不出去”的僵持局面，最终以求和结束。

#### 定式 3: 双方大子互忌残局
- **格局**：红方持单军长，蓝方持单司令但位置暴露，双方各有 1 颗地雷护旗；
- **棋理**：蓝司令若贸然深入容易误触暗雷或被暗炸弹同归于尽，红军长巡回游击。双方谁都不敢先发动决战冒险翻暗子，形成均势死锁。

**阶段定义**: 暗子 < 6 个，或 10 个行营全部被占用

### 4.1 死区判定标准

**死区完备度** (`junqi/analysis.py` lines 89-174):

```python
def fortress_score(state: GameState, seat: int) -> float:
    """评估 seat 方以军旗为核心的死区完备度，返回 [0.0, 1.0]
    
    算法（BFS 可达性）：
    1. 若军旗未翻开 → 返回 0.0
    2. 定义永久墙：
       a. 对方已翻开的明地雷
       b. 己方明地雷 + 对方工兵全灭
    3. BFS 从所有敌方威胁出发
    4. 军旗不可达 → 1.0；否则软评分
    """
```

**死区完备度解释**:
- **0.0**: 完全无防御，军旗直接暴露在敌方威胁下
- **0.3-0.5**: 部分防御，需要加强
- **0.6-0.8**: 良好防御，可以争取和棋
- **0.9-1.0**: 完美死区，几乎锁定胜局或和棋

**永戠墙判定逻辑**:
```python
perm_walls = set()
```

### 4.4 长距离调度

**铁路滑行规则** (`junqi/state.py` lines 349-375):

```python
def _rail_slides(board, start, attackable):
    """铁路滑行（一律走直线，不拐弯）：
    - 沿直线任意远
    - 不可越过任何棋子
    - 前线三通道不可穿越
    """
    from collections import deque
    results = set()
    queue = deque()
    for d in DIRS:  # 四个方向
        queue.append((start, d))
    
    while queue:
        pos, d = queue.popleft()
        dr, dc = DIRS[d]
        np = (pos[0] + dr, pos[1] + dc)
        
        if not in_board(np) or not is_rail(np):
            continue
        if frozenset((pos, np)) in CROSS_BLOCKED:
            continue
        
        t = board.get(np)
        if t is not None:
            if attackable(t, np):
                results.add(np)      # 攻击终点，路到此为止
            continue
        results.add(np)
        queue.append((np, d))  # 继续沿同一方向滑行
```

**调度技巧**:
1. **利用对角线** - 通过一次直角转弯到达对角位置
2. **接力传送** - 用多个棋子依次传递调动大子
3. **时间差利用** - 利用敌方需要 2 回合激活暗子的弱点进行长途奔袭

```python
def evaluate_piece(pc, context):
    base_value = PIECE_VALUES[pc.rank]
    
    # 位置因子
    pos_bonus = 0
    if is_camp(context.pos):
        pos_bonus = 10  # 行营内安全
    if is_rail(context.pos):
        pos_bonus += 5  # 铁路机动
    
    # 威胁因子
    threat_factor = 1.0
    nearby_enemies = count_nearby_enemies(context.pos)
    if nearby_enemies > 2:
        threat_factor = 0.7  # 被包围减价
    if nearby_bomb(context.enemy_pos):
        threat_factor *= 0.5  # 附近有炸弹危险
    
    # 战术价值
    tactical_value = 0
    if pc.rank == Rank.GONG:
        tactical_value = count_accessible_mines(context.pos) * 10
    if pc.rank == Rank.ZHA:
        tactical_value = largest_enemy_value_in_range(context.pos)
    
    return base_value * threat_factor + pos_bonus + tactical_value
```

```python
def evaluate_flip_safety(state, flip_position):
    """评估翻某个暗子的安全风险"""
    score = 0.0
    
    guards = []
    threats = []
    for neighbor in NEIGHBORS[flip_position]:
        piece = state.board.get(neighbor)
        if piece and piece.revealed:
            if piece.color == my_color:
                guards.append(piece.rank)
            else:
                threats.append(piece.rank)
    
    friendly_strength = sum(RANK_VALUE[r] for r in guards if r >= Rank.SHI)
    enemy_strength = sum(RANK_VALUE[r] for r in threats if r >= Rank.SHI)
    
    if friendly_strength > enemy_strength:
        score = 60000 + (friendly_strength - enemy_strength) * 5000
    elif enemy_strength > friendly_strength:
        score = 500 - enemy_strength * 1000
    else:
        score = 20000
    
    return score
```

**死区完备度计算**:
```python
def compute_fortress_completeness(state, flag_position):
    """计算以军旗为核心的死区完备度"""
    permanent_walls = set()
    
    for pos, piece in state.board.items():
        if piece.revealed:
            if piece.color == opponent and piece.rank == Rank.LEI:
                permanent_walls.add(pos)
            
            if piece.color == my_color and piece.rank == Rank.LEI:
                if opponent_has_no_engineers():
                    permanent_walls.add(pos)
    
    reachable = bfs_from_enemies(flag_position, permanent_walls)
    
    if not reachable:
        return 1.0  # 完全死区
    
    adjacent = NEIGHBORS[flag_position]
    blocked = sum(1 for n in adjacent if n in permanent_walls or has_friend(n))
    
    return 0.3 * (blocked / len(adjacent))
```
