> **阶段归属**：`P3 收尾 / P4 准入复审`
> **审查日期**：2026-09-01
> **审查范围**：`train_rl.py` / `mcts.py` / `net.py` / `encoder.py` / `selfplay.py` / `belief.py` / `hybrid_engine.py` / `benchmark.py` + `metrics/`、`models/elo_history.jsonl` 全量证据
> **实证脚本**：`_verify_root_cause.py`（只读诊断，可复现）
> **结论**：P4.4 长期挂机维持**不通过**；停滞根因比此前记录更深，本文给出五层根因、跨项目对标与 S0~S4 整改路线。

## 0. 基线验证（实测，非文档转述）

| 检查项 | 实测结果 |
|---|---|
| 全量单测 | **99/99 通过** |
| `best.pt` 50 题靶场 | MAE 0.3799、acc 34%，**50 题全部预测 Win（0 Draw）** —— 发布基线自身类别塌缩 |
| `bc_best.pt` | MAE 0.6929、开局 MAE 1.0000；Policy 可用（P2 Top-1 81.5%），价值头不可用 |
| `_candidate_gate.pt` | MAE 0.5690、acc 20%，预测 0 Win / 35 Draw / 15 Loss（Draw 塌缩） |
| 经验池（46,709 条 Value 样本） | **Win 10.5% / Draw 85.6% / Loss 3.9%** |
| `ref_vs_search2` | 候选得分 **0.25**（Epoch 6）——NN 目前弱于传统 search2 |
| 门控统计功效 | `eval-games=10`（每阶段 n=20）时 Wilson 下界 >0.5 需得分 ≥0.75；n=200 也需 ≥0.60 |

**核心结论：当前门控是"Draw 塌缩候选"对"Win 塌缩 best"的对抗，且门控判据在现有样本量下数学上不可通过——训练不是"学不动"，而是闭环多个环节同时失效。**

## 1. 训练无法提升的五层根因

### 根因 1（结构性死锁）：门控阈值 × 样本量 = 数学上不可能晋升

`decide_promotion()` 要求"至少一个子阶段得分的 Wilson 下界 >0.5"，但默认 `eval_games=10`（每阶段仅 20 局）。功效测算：

- n=20：得分 0.70 → 下界 0.481（否决）；**必须 ≥0.75 才可能通过**；
- 和棋密集规则下相近水平模型对抗得分天然收敛 0.5 附近，单阶段 75% 是碾压级差距。

**后果链**：永不晋升 → `pool_models` 永远只有 `best.pt` → 对手池永不扩张 → 无循环克制压力 → 无晋升（与根因 4 互锁）。这是 6 轮全部 `promoted=false`、Elo 恒 1500 的直接结构性原因。

### 根因 2（基线污染）：`best.pt` 是旧缺陷产物，且候选热启动自它

实测 `best.pt` 对 50 题全部预测 Win（含 25 题真值 Draw、8 题 Loss）。CHANGELOG "P0 收尾"一节已自认其为"旧缺陷下训练 3 轮的产物，建议 `--fresh`"，但 `run_training` 在无 checkpoint 时仍从 `best.pt` 热启动候选——**塌缩权重被继承进新一轮训练**。P4 计划"动作 1：选定干净启动基线"未执行。

### 根因 3（数据饥荒 + 标签失衡）：240 局 86% 和棋的经验池撑不起双头网络

- 6 epoch × 40 局 ≈ **240 局自对弈**；AlphaZero 量级百万局、Lc0 亿级，项目自身计划（§11）写明 2 万局起步，当前低两个数量级；
- Value 样本 **Draw 85.6%**：同构弱模型 + 70 步无吃子判和下"防守拖和"是优势策略。1/3 均衡采样只能缓解——Loss 桶仅 1,811 条，等权抽样等于反复重采、对极少数局面过拟合；
- `models_v3` 干净基线尝试仅跑 1 轮即停，未持续。

### 根因 4（对手多样性形同虚设 + 对手污染策略目标）

1. `opp_dict` 仅在 `len(pool_models) > 1` 时注入，而池扩张依赖晋升（根因 1），**"25% best 对抗"分支从不生效**。实际退化为 50% 镜像 / 35% expert-d2 / 10% greedy / 5% random，且无逐轮占比日志；
2. **对手（expert/greedy）走子时，其单步动作被写成 one-hot 记入 Policy 训练目标**，违背 AlphaZero 语义（策略目标必须来自己方 MCTS），把专家保守防御风格强行蒸馏进策略头，进一步固化"不求胜只求不和"行为；这些步还不产生 Value 叶子样本。

### 根因 5（Value 训练/评测分布失配 + 靶场自身不可达）

1. **模式失配**：全部 Value 训练样本来自 MCTS 叶子的**世界模式**编码（通道 35=1.0），而靶场、GUI、HybridEngine 全在**公共模式**（通道 35=0.0）下评测。价值头从未见过公共模式输入；
2. **靶场标签自相矛盾**：中盘题 `true_value` 是连续值（±0.2~0.8）但 `true_val_class` 是极端类。类别全对的模型标量≈±1，对 0.5 的题必产生 0.5 误差——**"总体 MAE <0.15"目标与三分类头数学上互斥**，误导熔断判断；
3. 塌缩告警阈值过松（单类 ≥90% 才报，当前 Draw 70% + MAE 0.57 不报），且主循环只写告警字段、未接自动暂停。

### 次级问题

- `HybridDecisionEngine` 只做 K=4 世界 Policy 平均 + 战术加权，无逐动作多世界搜索；结合 `ref_vs_search2=0.25`，P4.2 棋力验收远未达成；
- 尾盘温度 0.2 在趋和局面下进一步压制探索，破死区/围猎暗子的决胜样本永远采不到；
- `best.pt` 全 Win 塌缩与候选全 Draw 塌缩互为镜像：价值头在稀疏终局信号下对初始化先验极度敏感，缺乏锚定信号即塌向一侧。

## 2. 对标其他棋类 AI 训练范式

| 项目 | 关键做法 | 对军棋翻棋的迁移结论 |
|---|---|---|
| **AlphaZero** | 百万级自对弈、800 sims、前 30 手高温、400 局门控 | 当前数据量差 3~4 个数量级；门控须放大到每场景 ≥200 局（项目 §7 协议已写明，从未执行）；前中期温度应升不应降 |
| **Leela Chess Zero**（高和率，与军棋最像） | WDL 头（本项目已采用，方向正确）、开局书强制多样性、滑动窗口回放 | 高和率防塌缩的核心是**起始局面多样性**：固定发牌种子集、中盘评测集注入自对弈起点、不对称子力开局，而非对称镜像自对弈 |
| **KataGo** | WDL 外回归 `scoreLead` 辅助头、动态和值建模 | 在不违反"纯终局奖励"红线前提下，加**监督式辅助头**回归 `material_diff`/`fortress_score`（`analysis.py` 确定性可算），给价值头密集锚定信号 |
| **PSRO / AlphaStar League** | 对手池是一等公民 | 打破"池依赖晋升、晋升依赖池"死锁：best/专家/贪心/随机**无条件**进 Worker |
| **暗棋（Banqi）学术线**（JAIST） | ISMCTS + 确定化采样；小棋盘残局近可解 | 尾盘 10~15 子接近可解：用深搜索/长 rollout 给 `gen_endgame` 局面打经验 W/D/L 标签（tablebase 式引导） |
| **MuZero** | 学习隐式动态模型 | **暂不适用**：瓶颈在价值信号与数据量，不在动态建模 |
| **Lc0/Minigo 工程** | 候选对"阶梯对手"评 Elo | 门控信号升级为对 greedy/search2/旧快照的 Elo 阶梯；`ref_vs_search2` 从"仅记录"升级为晋升硬条件 |

**方向总结**：正确顺序是 **(1) 修价值监督信号（蒸馏+辅助头+公共模式样本）→ (2) 课程/起始局面多样化制造决胜局 → (3) 放量自对弈 → (4) 足够功效的统计门控验收**。当前项目是倒着做的。

## 3. 整改路线图（S0–S4）

### S0 — 干净基线与测量修复（阻塞一切后续）

1. 修复靶场标签矛盾：中盘 15 题 `true_value` 改为与类别一致（Win→+1 / Loss→−1 / Draw→0）；新增 Brier 分数与预测熵监控；塌缩告警阈值 0.90→**0.70**；
2. 基线重建：候选热启动优先 `bc_best.pt`（策略头 Top-1 81.5% 可用），新增 `--rebase-baseline` 把旧 `best.pt` 备份为 `best_legacy.pt` 并以 BC 模型重建发布基线；
3. 三模型基线快照落盘 `metrics/baseline.json`（模型哈希 + 靶场 + 对 search2 得分）。

### S1 — 打通晋升与对手池死锁

1. `opp_dict` 无条件注入（池只有 1 个模型时也传 `best_path`）；对手配比显式配置化；
2. Worker 返回逐局对手类型，主循环写 `elo_history.jsonl` 的 `opponent_mix`；
3. **删除对手走子的 one-hot Policy 目标**：对手分支不再记 `root_records`，仅镜像/NN 方的 MCTS 访问分布可作策略目标；
4. 快速门控 `--eval-games` 默认 10→**32**；晋升改善条件改为 **overall Wilson 下界 >0.5 且无阶段得分 <0.3**（子阶段下界 >0.5 仅保留给 200 局正式协议）；
5. `ref_vs_search2` 升级为硬条件：**≥0.5 且不低于上一轮**（未跑参考对抗时跳过）；
6. Elo 与晋升解耦：每轮按门控 overall 得分更新 Elo 记录。

### S2 — 修复价值信号（训练能否提升的分水岭）【已实施，2026-09-01，待 S3 复验】

1. **公共模式 Value 样本**：自对弈每手根局面以终局 z 为标签同步记录公共模式样本，与世界模式叶子 1:1 混合训练；
2. **专家价值蒸馏预热**：用 `ExpertAgent`（depth 3~4，Star1+QSearch+死区评估）给中盘/残局局面打伪标签，监督价值头 2~3 epoch 后再进自对弈（监督信号，非奖励塑形，不违反硬约束）；
3. **辅助回归头**（可选）：价值头旁加 1 维回归分支监督 `material_diff`，权重 0.1（KataGo scoreLead 类比）；
4. **决胜局课程**：`gen_endgame` 按 `material_balance` 分层，±0.3 以上不对称残局续弈概率提到 0.3；中盘评测集不对称局面以 0.1 概率注入自对弈起点；
5. 温度表上调 `{开局:1.2, 中盘:1.0, 尾盘:0.5}`，前 20 手强制探索噪声。

### S3 — 熔断落地 + 中等规模验证

1. 熔断表接入 `run_training` 主循环（重复率、单类占比、MAE 退化、无胜负样本 → 自动暂停并保留现场）；
2. 修正后门控跑 3~5 Epoch × 120 局（固定种子），逐轮记录对手占比、终局原因、Value 类别分布、靶场三指标、MCTS 根访问熵；
3. 验收：`repetition<5%` 保持；Value 三分类 acc 相对基线单调不降且无单类 >70%；`ref_vs_search2 ≥0.35` 且逐轮不降。

### S4 — 放量与正式晋升

1. 提至每轮 200 局、`sims` 60→120，累计 ≥2 万局（对齐计划 §11）；
2. 正式晋升按 §7 协议：每场景 200 局、先后手各半、Wilson + Value 双门控（`decide_promotion` 补入靶场指标否决项）；
3. 晋升后快照入池，开启 PSRO 式循环；届时再评估 P4.2 逐动作多世界搜索（PIMC + Value 聚合）。

## 4. 硬约束合规性

- 不触碰：`RuleConfig`/APK 规则、终局奖励 `z∈{+1,0,−1}`（蒸馏/辅助头是监督信号非奖励）、单一网络架构、"不以 loss 宣布变强"；
- 和棋标签语义不变：合法规则和棋仍是真实 Draw，只通过采样配比、课程生成、对手多样性改善信号；
- 文档同步：每阶段落地后更新 README 与 `docs/CHANGELOG.md`，结论回填 `P4_EXECUTION_PLAN.md` 复审表。

## 5. 最终结论

1. **P4.4 长期挂机维持不通过**，且原因更深：`best.pt` 基线污染、门控统计功效不足、对手池死锁构成"永不晋升→永不多样化→永不提升"闭环；
2. **第一根因不是搜索或规则链路**（P0/P4 整改后已修复，重复和棋 0/32 为实证），而是**价值监督信号断裂**：模式失配 + 86% 和棋标签 + 无蒸馏冷启动；
3. **翻盘优先级**：S0 干净基线 + 靶场修正 → S1 门控/对手池解锁 → S2 公共模式样本 + 专家蒸馏 + 决胜课程 → S3 熔断与中规模验证 → S4 放量。S2 是其他棋类 AI 反复验证的决定性一步：先让价值头有锚，再让自对弈有量。
