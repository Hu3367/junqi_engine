## 0. 背景与目标转变

- **问题**：专家对局实测约 75% 为无吃子判和；NN 自博弈历史更差（P3 复审 96 局 0-1 胜负）。z=0 的和棋样本无学习信号，"循环走子到判和"是垃圾数据的主要来源。
- **核心任务转变**（2026-09-13 用户决策）：从"通过简单对弈不断加打分限制"（该路线已随 hybrid_engine 加性常数清除而正式关闭）转为"**快速启动自对弈、产出大量高价值数据**"。
- **已落地的三项机制**（详见 CHANGELOG 2026-09-13 第七节）：
  1. 生成/评测夹具分离（`GENERATION_CFG`：无吃子判和 70→120 步、循环判和 3→4 次；评测门控保持官方规则）；
  2. 自博弈认输（`ResignTracker`：根 Value ≤ −0.95 连续 8 己方回合、ply ≥ 40，按官方 code 21 语义提前终局）；
  3. 和棋局 quiet ≥ 60 尾部样本段不入回放池 + 残局/中盘课程采样沿用既有挂钩。

|---|---|---|---|---|---|---|

| 2 | 63% | 2% | 0.845 | 12% | 0.438 | 1494 |
| 3 | 66% | 12% | 0.659 | 58% | 0.406 | 1494 |

终局原因分布（Epoch 6）：no_capture 39% / immobilized 33% / resign 24% / flag 3%。每轮产出 ~7-9 万 Policy、20 万 Value（buffer 容量上限）样本。

**结论**：
- ✅ 数据工厂达成目标：决胜率从历史 ~3% 提升到稳定 60-69%，认输回路自增强（2%→27%）；
- ❌ **Value 校准崩坏**（60%→12%→58%→40%→16%→28% 剧烈失稳）成为第一优先问题；
- ❌ 门控 5 轮 0.406-0.531 无趋势，未晋级——策略 loss 在降（2.35→2.25）但强度未分离。

## 2. 对照实验 A：认输关闭重校准（`--no-resign --fresh`，2 × 100 局）

设计动机：当时的工作假设是"认输标签自证投毒"（未校准的 Value 头误判 → 认输 → 生成 ±1 标签 → 强化误判），故用回滚开关 + 清空 buffer + 从 value_distilled 热启动做隔离。

| Epoch | 决胜率 | Value MAE | 三分类 | 门控 | Elo |
|---|---|---|---|---|---|
| 1 | 55% | **0.494** | **60%** | **0.562**（迄今最高） | 1502 |
| 2 | 57% | **0.498** | **60%** | 0.500 | 1502 |

**当时结论（后被实验 B 修正）**：验收线（MAE<0.5、准确率>50%）双达标，认输投毒假设成立。

## 3. 验证实验 B：认输开启 + 认输局样本只进 Policy 池（1 × 100 局）

设计：认输照常触发（保吞吐），但认输局的 Value 样本一律丢弃（其 ±1 标签来自模型自身判断而非客观终局），仅保留 Policy 样本。从实验 A 的重校准检查点续训。

| 指标 | 预期 | 实际 |
|---|---|---|
| 认输率回升至 20%+ | ✗ | **仅 2%** |
| Value MAE < 0.5 保持 | ✗ | **0.835 / 准确率 16%——再次崩塌** |
| 门控 / Elo | — | 0.531 / **1503**（新高） |

**关键证据：Value 在认输标签完全缺席（认输率 2% 且已隔离）的情况下依然崩塌**——"认输投毒"是主因的假设被推翻。

## 4. 修正后的诊断（当前有效）

1. **高认输率是病症，不是收益**：27% 的认输率对应的是"过度自信且错误"的 Value 头（MAE 0.94 = 自信地错）；校准健康的 Value 头很少输出 ≤ −0.95 的极端置信（健康状态下认输率自然回落到个位数）。"认输率回升 20%+"这一验收标准已撤回。
2. **真因：联合 RL 训练摧毁 Value 校准**。证据链：
   - 实验 A 的成功主要来自 `--fresh` 的干净热启动（value_distilled 的 Value 头在冻结主干、精选标签上单独训成）+ 同质 buffer，而非仅仅关闭认输；
   - 实验 B 在健康检查点上**只训 1 轮**即崩回 16%，而该轮 Value 训练输入与上轮本质相同（无认输标签）；
   - buffer 内 Value loss 很低（0.093）但靶场三分类 16%——教科书式"拟合回放池、丢失泛化"：Policy 主导的联合优化使主干特征漂移，Value 头坐在漂移的地基上。
3. **认输局样本只进 Policy 池的隔离措施正确且保留**（消除一条确认偏误通道），但它不是充分修复。
4. 训练循环的其它观察：worker 推理在 CPU（约 0.44s/手的主要成分，GPU 批量推理是后续提速空间）；决胜局以困毙为主（38-59%），拔旗极少（3-7%）。

## 5. 待执行的修复方案：每轮 Value 重锚（re-anchor）

**方案**：每轮 RL 联合训练后追加一个"冻结主干、仅训 Value 头"的短微调段，数据为回放池中客观终局样本（可选掺入 `datasets/p1_v3` 官方客观标签），直接对抗每轮的主干特征漂移。机制与 value_distilled 热启动同源，管线现成，改动集中在 `run_training` 的一处钩子。

**验收线**：连续 2 轮 Value MAE < 0.55、三分类准确率 ≥ 45%（允许联合训练下的合理漂移，不再要求 60%）；认输率稳定在低位；门控得分趋势向上。

## 7. 经验教训

1. **认输率是病症指标**：认输率异常升高 = Value 头过度自信且错误，不是吞吐收益。
2. **实例缓存在 unique-state 负载下无效**：搜索/估值热路径中绝大多数状态只被评估一次，缓存命中不了；调用量才是主因（性能优化教训，详见 CHANGELOG 性能节）。
3. **启发式剪枝必须过人工验证的战术回归测试**：内层翻棋剪枝 2/3 在快照 30/30 一致的情况下仍翻转了深度 3 的用户验证场景（第 19 手）。
4. **对照实验要隔离热启动差异**：实验 A 把"fresh 热启动"与"关认输"两个变量混在一起，导致把重校准错误归因于关认输——实验 B 才暴露真因。
5. **训练中途不动参数**：所有调整在轮次边界依据完整数据执行；每轮固定种子门控保证跨轮可比。

## 8. 方案验证与落地（2026-09-14 本轮）

### 8.1 对 §5 方案的验证结论：方向正确，但需三处修正

**(a) 根因是学习率，不是"缺少重锚"（受控实验）**。同一 6 块共享主干、同一 p1_v3 官方客观标签、同样联合策略+价值损失，只改 lr：

| lr | 起始 | 1 轮（711 步） | 2 轮 | 3 轮 | 策略模仿 top-1（3 轮后） |
|---|---|---|---|---|---|
| 1e-3（运行默认） | 平衡acc 0.763 / MAE 0.266 | 0.567 / 0.454 | 0.544 / 0.491 | 0.546 / 0.486 | 0.218 |
| 1e-4 | 同上 | 0.713 / 0.320 | 0.716 / 0.313 | 0.713 / 0.319 | 0.261 |

即：1e-3 对共享主干微调**一个 epoch 就砍掉约 20 个点** Value 平衡准确率，且策略学得更差；1e-4 两者都更好。（代理实验：策略目标用 p1_v3 专家着法替代自博弈 MCTS 分布，未分离 policy/value 两项损失的贡献。）

**(b) "冻结主干、仅训 Value 头"能预防、不能修复**。对已漂移主干（`models/candidate_latest.pt`，实测 100% 单类塌缩）做头-only 重锚：2,372 步后平衡准确率上限 0.344（≈随机 0.333），MAE 反升（0.488→0.641）；用健康 v2 头初始化亦被拖回 0.350；解冻 `in_conv`+末块 2 轮无恢复（0.310-0.312）。**结论：重锚是每轮保险丝，已漂移候选不可救，只能从健康基座重启。**

**(c) 三处具体缺陷**：
1. `train_value_from_p1_dataset` 首轮打印引用未定义变量 `mae` → 必然 `NameError`（已用 256 条样本复现），CLI `distill_value --p1-dir` 路径不可用且零测试；
2. 热启动接线只认 `value_distilled.pt`（p1_v3/test 平衡acc 0.318 / MAE 0.599，84% 预测画和棋），而 `value_distilled_v2.pt` 为 **0.735 / 0.288**；两者策略头权重逐位相同（差异 0.00000）；
3. 验收线缺陷：p1_v3 上"恒定预测单一类别"的塌缩模型 MAE 仅约 0.50 < 0.55 阈值（实测 `candidate_latest` 即全 Loss 塌缩且 MAE 0.502），且原靶场仅 36 题（17/11/8），accuracy 粒度 2.8%；另实测策略池严重失衡（opening 8,589 / midgame 3,208 / endgame 66,409），固定权重使 midgame 样本每轮被重复曝光约 12 次。

### 8.2 已落地变更（P3 修订，详见 CHANGELOG 2026-09-14）

默认 lr 1e-4；热启动优先 v2；每轮 Value 重锚（池客观终局样本 70% + p1_v3 30%，冻结主干，实测约 2-3 秒/轮，`--no-reanchor` 可回滚）；验收探针改为 p1_v3/test 独立留出集（9,381 条）的平衡准确率（线 0.45）+ MAE（线 0.55）+ 塌缩告警；修复崩溃并抽出 `load_p1_arrays` / `value_health_metrics` / `evaluate_value_health` / `train_value_head_only` 共用助手；补齐 `junqi/__main__.py` CLI 接线（`train_rl.py` 内的 `main()` 非实际入口）。测试：`tests/test_value_reanchor.py` 11 项；全量 258 passed / 3 skipped。

### 8.3 冒烟验证（1 轮 × 4 局）与新发现

全链路通过：热启动 v2 → 自博弈 → lr 1e-4 联合训练 → 重锚（3 epoch，池 3,957 + p1 1,696 = 30%）→ 探针 **平衡acc 0.686 / MAE 0.342 / 无塌缩 ✅** → 靶场回归 56% → 门控 n=8 记录 → 落盘。单轮耗时 111.9s。

**新发现（重要）**：v2 的 Value 头在自博弈状态上是**分布外**的——实测在池样本上的 CE：公共模式 **6.24**、世界模式 **7.54**（近乎"自信地错"），而同样这批标签一轮联合训练后 CE 降到 **1.09**（≈ ln3，即转为无信息）。含义有两点：
1. v2 在 p1_v3 上的 0.735 **不等于**它在自博弈搜索里可用；重锚以池样本为主（70%）正是为此提供自博弈分布的锚定，30% p1_v3 保留外部客观校准；
2. 因此**需要两个探针**：p1_v3/test（外部客观锚，识别塌缩/遗忘）+ 池内 v_loss（自博弈分布可用性）。单看任何一个都会被误导——历史教训是池内 v_loss 0.093 时靶场仅 16%，而 v2 是靶场 0.735 但池内 CE 7.5。

|---|---|---|---|---|---|---|---|---|
| 1 | 7.895 | 0.662 | 0.595 | 0.456 | False | ✅ 连续1 | 1466s | 1499 |
| 2 | 1.480 | 0.662 | 0.603 | 0.442 | False | ✅ 连续2 | 1513s | 1497 |

**结论：验收线达成（要求连续 2 轮，实际连续 5 轮），Value 校准不再随联合训练崩塌**——对比历史同指标（靶场三分类）的剧烈震荡 60%→12%→58%→40%→16%→28%，以及实验 B 单轮即崩回 16%。探针指标呈缓升趋势（0.595→0.639），MAE 同步下降（0.456→0.408），预测分布始终接近真值分布（Win/Draw/Loss 约 2.2k/4.7k/2.4k vs 真值 2.1k/5.1k/2.1k）。

- 局长 296-318 手、决胜率 63-70%，与历史基线（295-330 手 / 60-69%）一致——即修复未改变对局形态，只改变了 Value 校准；
- 池内 v_loss 稳定在 1.5-1.8（历史 v1 头曾降到 0.09 = 记忆回放池），说明新头保留了对自博弈结果真实不确定性的表达，而非背下标签；
- 靶场（36 题）三分类在 0.24-0.66 之间剧烈跳动 —— 与预测的 ±13-16% 噪声带宽吻合，**佐证其不可作为验收依据**（已降级为回归探针）；
- 轮内门控 n=16 得分 0.438-0.531 无趋势（功效上限需 +191 Elo），符合预期，故晋级判定交由批次 2 的形式化 SPRT 门控（n=200）。

### 8.6 批次 2 形式化门控结果（n=200）：**不重定 best.pt**

配置：候选 `models/candidate_latest.pt`（批次 1 第 5 轮）vs 基准 `models/best.pt`（09-01），`nn_mcts_20` 对 `nn_mcts_20`，100 组种子 × 先后手互换 = 200 局，配对同牌。报告：`reports/gate_nn_mcts_20_vs_nn_mcts_20.json`。

| 指标 | 数值 |
|---|---|
| 战绩 | 胜 25 / 和 144 / 负 31 |
| 得分率 | **0.4850**，Wilson 95%CI [0.4167, 0.5539] |
| 仅计胜负局胜率 | 0.4464（n=56），Wilson [0.3239, 0.5759] |
| 配对 z 检验 | z=-0.973，p=0.331 |
| SPRT (elo0=0, elo1=65) | LLR=**-20.809** → **accept_h0** |
| 晋级判定 | **promote = False** |

**终局拆分暴露和棋病**：200 局中 144 局和（72%），其中 no_capture 141、repetition 3；只有 56 局分出胜负（immobilized 25 胜 / 31 负）。即在 sims=20 的门控条件下，双方 72% 的对局走到 70 步无吃子判和——**这既让门控信息量缩水（只有 28% 对局携带胜负信息），也说明当前策略对之间缺乏区分度**。

**决策与含义**：
1. 依 AGENTS.md 硬约束（"不得只因训练 loss 下降就覆盖 best.pt"），**不更新 best.pt**——候选与旧基准无统计差异，SPRT 反而以 LLR=-20.8 明确接受 H0；
2. 结合 §8.4：**批次 1 修好的是 Value 校准（必要条件），但没有带来可测的棋力提升**——这与 §8.1 的分析一致：强度瓶颈在**信号质量**（sims=20 的自我蒸馏、50% mirror 对手、无外部梯度），即批次 3/4 的范畴，而不是 Value 校准本身；
3. 门控功效的经验值也得到确认：n=200 时判据约需 +49 Elo，而本次 56 局胜负样本的胜率 0.446 连方向都是负的，故"未见改善"这一结论是可信的（不是"测不出"）。

> ⚠️ 证据归档注意：`run_gate` 的 JSON 文件名只由 spec 名派生（`gate_{a}_vs_{b}.json`），两次门控都用 `nn_mcts_20` 对 `nn_mcts_20`，故批次 3 的门控 **覆盖**了批次 2 的 JSON。文本报告已分别归档为 `reports/archive_gate_b2_candidate_vs_best_n200.log`（批次 2）与 `reports/gate_b3_adaptive_vs_b1_fixed.log`（批次 3），批次 3 JSON 另存 `reports/gate_b3_adaptive_vs_b1_fixed.json`。后续门控应用不同 spec 名或给 `run_gate` 加 out_name 参数。

### 8.7 批次 3 首项验证结果（adaptive 池权重，5 轮 + 对比门控）：**无显著差异**

训练 5 轮（其余配置与批次 1 完全一致，唯一变量 `--pool-weights adaptive`）：探针 p1_v3/test 平衡acc 0.595 / 0.605 / 0.625 / 0.624 / 0.623，全程达标、无塌缩；p_loss 一致地更低（3.37-3.52 vs 批次 1 的 3.62-3.80）——按 AGENTS.md 纪律，**loss 更低不构成变强证据**。

对比门控（adaptive 候选 vs 批次 1 fixed 候选，200 局）：

| 指标 | 数值 |
|---|---|
| 战绩 | 胜 10 / 和 183 / 负 7 |
| 得分率 | 0.5075，Wilson [0.4387, 0.5760] |
| 仅计胜负局 | 0.5882，但 **n=17**（和棋率 91.5%） |
| 配对 z | z=+0.773，p=0.4395 |
| SPRT | LLR=-73.322 → **accept_h0** |
| 判定 | promote = False |

**结论：池失衡修复（曝光比 34.5→4.5）本身不改变棋力**。两次形式化门控共同指向同一件事：

1. **批次 1 已解决 Value 校准问题**（必要且已验证），但批次 1-3 的全部改动都**没有**带来可测的棋力提升；
2. **真正的下一个瓶颈是"区分度"本身**：同源模型之间 72%（vs 旧 best）到 91.5%（vs 批次 1）的对局以 no_capture 判和收场，门控只剩 17-56 局胜负样本，训练里 z=0 样本又被丢弃——**信号既在评测端稀薄、又在训练端被裁掉**；
3. 因此下一步应优先做 §8.1 已点明但未动的两件事：**提高搜索质量/有效 sims（批次 4，C++ nn_mcts 或 GPU 批量推理）** 与 **降低 mirror 占比、提高 expert 占比（批次 3 剩余项中的对手结构）**，而不是继续在池权重这类"数据配比"上做文章。

**重锚的一个可复用发现**：批次 1 与批次 3 的联合训练 Value 头必然不同（起始权重不同、p_loss 不同），但**重锚后的探针指标在第 1 轮完全相同**（0.595/0.456、预测分布逐类相同），第 2 轮后才开始分化。说明重锚（51k 锚样本 × 3 epoch × lr 5e-4）的输出**主要由锚数据决定，而非由传入的头部决定**——它实为"每轮用客观数据重新推导 Value 头"，这正是它能稳定校准的原因；副作用是**该探针对策略侧变化不敏感**，故策略进步必须用门控而非探针判定。

### 8.9 三次形式化门控的合并判读（核心瓶颈已明确）

| # | 对比 | n | 战绩 | 得分率 | 决胜局数 | SPRT |
|---|---|---|---|---|---|---|
| 1 | 批次1候选 vs 旧 best(09-01) | 200 | 25 / 144 / 31 | 0.4850 | 56（28%） | accept_h0 |
| 2 | adaptive池权重 vs 批次1 | 200 | 10 / 183 / 7 | 0.5075 | 17（8.5%） | accept_h0 |
| 3 | diverse对手结构 vs 批次1 | 200 | 8 / 184 / 8 | 0.5000 | 16（8%） | accept_h0 |

三次门控一致地 `accept_h0`，且**和棋率依次恶化 72% → 91.5% → 92%**。这已不是"门控功效不足"能解释的——它与训练端的证据合起来指向一个更根本的结构问题：

1. **自博弈产出的数据里几乎没有胜负信号**：同源网络之间 92% 的对局以 no_capture 判和（70 步内无吃子），而训练端又把和棋局的 z=0 尾部样本裁掉（QUIET_TAIL_CUTOFF）——**信号在生成端就稀薄、在训练端再被裁一次**；
2. 故批次 1-3 的所有改动（Value 校准、池权重、对手结构）都无法转化为可测棋力：它们改善的是"数据配比与校准"，而缺失的是**胜负本身**；
3. **"92% no_capture 和棋"需要单独诊断**：连续 70 步双方都没有吃子动作，更像是"双方都不发起有效进攻"而不是"势均力敌的僵持"（与"决胜率 60-70% 但拔旗仅 4%"、以及门控里 immobilized 主导一致）。这才是当前第一优先问题。

**下一步优先级（按证据）**：① 诊断 no_capture 和棋的成因（策略是否系统性回避进攻动作；进攻动作在搜索/编码中是否被低估）；② 用批次 4 的推理提速把 `sims` 从 20 提上去，让搜索能看穿"进攻-被反杀"的战术线；③ 之后才谈其余超参（lr 余弦、池权重）。

### 8.10 和棋成因诊断（2026-09-14 补充，工具 `scratch/diagnose_draws.py`）

**方法**：对镜像自对弈逐手记录进攻面统计（合法动作构成、双方明子数、子力差、有攻击机会时是否进攻），NN 用 `nn_mcts_20`（24 局 × 3 种判和阈值），对照组用 `expert2`（8 局 × 3 种阈值）；另从门控 200 局存档提取每局吃子价值。日志：`reports/diagnose_draws_nn24.log`、`reports/diagnose_draws_expert.log`。

**(a) 和棋不是"不战斗"**：门控 182 局 no_capture 和棋的**局长中位 320 手**、每局被吃子力中位 **924 分**（全军约 1009 分，即换掉近一整军）；200 局仅 3 局零吃子。和棋局**净子力差绝对值中位仅 75**（决胜局 168），182 局中 65 局净差恰为 0。

**(b) NN 系统性回避交火，专家不**：

| 指标（官方规则口径） | NN 镜像（24 局） | expert2 镜像（8 局） |
|---|---|---|
| 每局攻击次数 | 13.5 | **25.8** |
| 有攻击机会的决策点占比 | 71-76% | 51.7% |
| **有机会时实际选择攻击** | **5.6-6.6%** | **18.1%** |
| 被吃子力合计中位 | 868 | **1416** |
| 净子力差绝对值中位 | ~0（插桩）/ 75（门控） | **184** |
| 拔旗占比 | 1.5%（门控 3/200） | 12.5%（1/8） |
| 判和构成 | no_capture 为主 | **repetition 为主**（5/8） |

**(c) 规则层面的攻击稀缺是共同背景**（`state.py::_attackable`，与 APK 对齐）：暗子不可被攻击、禁止自杀式攻击、行营内不可攻、军旗仅工兵可吃——每手合法攻击选项均值仅 0.9-2.0 个（占合法动作约 3-6%）。专家在更少的机会下（51.7% 决策点有机会）进攻了 3 倍多的频率。

**诊断结论**：
1. **和棋倾向部分是博弈固有的**：专家对专家也 75% 和棋（6/8）——翻棋的不完全信息 + 行营/暗子规则使优势难以转化，这设定了"可分胜负空间"的上限约 25%；
2. **但 NN 的问题更重且性质不同**：专家用**不对等交换制造净差**（184 分）并拔旗（12.5%），NN 只做**对等交换**（净差≈0）且几乎不拔旗（1.5%）；NN 的和棋是 no_capture 型（静默耗尽），专家是 repetition 型（动态绕圈）。胜负空间被 NN 从 ~25% 压缩到 8%，且方式退化为困毙（16 局决胜里 13 局 immobilized，败方被吃光至 ~1009 分）；
3. **故瓶颈在网络与搜索，而非规则目标**：政策头在有攻击机会时 94% 选择走空位/翻子——这正是自博弈 RL 在 92% z=0 样本上自我强化的均衡（进攻有风险、静默至少不输）。下一优先项回到 §8.9 的 ②：提高 sims（搜索看穿"进攻-反杀"线）与批次 4 提速；数据侧可考虑对"进攻后取胜"的片段做课程加权（不引入中间奖励的前提下调整采样权重）。
