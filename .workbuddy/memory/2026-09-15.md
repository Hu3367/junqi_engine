## 全项目只读审查（未修改任何业务代码）

对 junqi_engine 做了一次方案层 + 代码层的全面审查。核心结论（供后续修复优先级参考）：

### 致命级（会导致训练完全无效）
1. `junqi/train_rl.py:1162/1174/1179` 热启动分支 `net = JunqiNet.load_from_file(...)` 重新绑定 `net`，
   但 `optimizer` 在 `:1114` 已绑定旧 net → 优化器与新网络脱钩，首轮起权重零更新。
   只有断点续训路径（`:1143-1152` 走 `load_checkpoint` 就地载入）正确。
2. `junqi/train_rl.py:1217` `torch.load(opp_path)` 取到的是 `net.save()` 的包装字典
   （键 `model_state/in_channels/...`），worker `:537` 却用 `load_state_dict(..., strict=False)`
   → 键全不匹配、静默通过 → **自博弈 "best 对手" 是随机初始化网络**（OPP_MIX 约 25% 对局）。
3. `junqi/expert/` 11 个模块引用不存在的 `state.Move` / `get_piece_at` / `current_turn` /
   `config.PIECE_RANKS` 等 → 整包 ImportError，属僵尸代码，主流程用的是 `junqi/search.py`。

### 方案/路线层
- `train_rl.py:596-760` 自建了一套门控（wilson/decide_promotion/evaluate_gate），
  与 `junqi/eval_gate.py:run_gate`（配对同牌 + 先后手 + Wilson + 三元 SPRT，质量更高）并行存在；
  训练主循环只用前者，且两方向用 `seed+i` 与 `seed+100000+i` **非配对同牌**，`device` 硬编码 cpu。
- 方案 `AI_TRAINING_AND_HUMAN_PLAY_PLAN.md:244` 要求认输局 ±1 计入 Value，
  代码 `train_rl.py:980-982` 相反（只留 Policy）。代码正确（防自证回路），方案未回写。
- CLI/函数默认数据集仍指向 `datasets/p1_v1`、`p1_v2`，而 anchor 用 `p1_v3` → 两套口径并存。

### 运营/性能
- `models/candidate_latest_buffer.pkl` 单文件 **3.8 GB**（×3 目录≈11 GB），每轮无条件全量 pickle 落盘。
- `venv/` 4.7 GB 位于工程目录内。
- MCTS 每次模拟 batch=1 前向；`predict_state` 内部 `legal_actions()` 计算两次；
  `position_key()` 整盘排序在根候选循环里逐动作构造。
- `search.py:769-771` IDS 早停判据为"总耗时 > 25% 预算"，语义错误（应为"预估下一层超限"），
  超时时返回 `(acts[0], -inf)`，会污染 `train_search_distill` 的蒸馏教师分布。
- `search.py:706` 根节点用收窄 alpha 窗口搜后续动作，fail-low 的上界分被当作精确分写入
  `stats.root_scores`；`ai.py:329-336` 回退路径把 1e5 量级 move-ordering 分当估值分返回 GUI。
