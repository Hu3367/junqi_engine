# BC 验收复核：`reports/p2_bc_report.md` 是否支撑"克隆成功 / 可进 P3"

> **阶段归属**：`P2`（行为克隆与搜索蒸馏）
> **复核对象**：`reports/p2_bc_report.md`（2026-09-17 21:56:35，模型 `models/bc_best.pt`）
> **复核时间**：2026-09-17
> **复现脚本**：`scratch/probe_bc_verdict2.py`、`scratch/probe_leak_cross.py`（只读，不改工程文件）

---

## 0. 结论

1. **不能判定"克隆成功"。** 报告里可用的只有 Policy 一项（Top-1 24.90% vs 随机 2.34%），
   Value 一项是**错的**，而 P2 验收 4 条里只覆盖了 1.5 条。
2. **本次重训是"平手"，不是进步也不是退步。** 之前被当成基线的高分（52.90% / 74.61%）
   **全部来自跨数据集版本的对局重叠（评测泄漏）**，不是模型能力。同一模型在真正未见的划分上
   只有 24.39%。新旧 BC 的诚实水平都是 ~24–25%。
3. **不建议现在就把它当 P3 的起点。** 主要障碍不是策略（24.9% 的弱先验对 MCTS 尚可用），
   而是 **Value 头在未见对局上零判别力（胜负 AUC 0.4899）**，以及
   `models/value_distilled_v2.pt` 刚在 21:56 被用新 BC 重建（诚实 val 平衡准确率 0.3247，低于 1/3 随机），
   而 `train_rl` 的热启动**优先取它**。

## 2. 训练曲线：泛化在第 4 轮就见顶，之后 11 轮纯记忆

来源 `models/bc_best_history.json`（15 轮，`train_bc.py --epochs 15`，约 5.3s/轮）：

| epoch | train CE | train Top-1 | **val Top-1** | val loss（=P+0.5V） |
|---|---|---|---|---|
| 1 | 2.9705 | 19.95% | 21.84% | 3.624 |
| 2 | 2.7456 | 24.15% | 22.98% | 4.414 |
| 3 | 2.4644 | 31.35% | 24.76% | 4.779 |
| **4** | 2.0327 | 42.04% | **25.36%** ← 保存的权重 | 5.057 |
| 5 | 1.6096 | 52.89% | 25.31% | 5.942 |
| 10 | 0.3897 | 90.15% | 24.16% | 8.361 |
| 15 | 0.0985 | **98.63%** | 24.27% | 9.187 |

- `models/bc_best.pt` 里保存的是 **epoch 4** 的权重（元数据 `epoch: 4`）。

  价值头能把训练局"这盘是谁赢"背下来（96.3%），一到新对局就崩 —— 说明它学的是**对局指纹**，
  不是局面评估。

## 3. Value 头：报告的结论不成立

在 `p1_v3/test`（9381 个有标签样本）上：

- 混淆矩阵（行=真实 W/D/L，列=预测）：`W[492,1142,485]`、`D[1037,3030,1077]`、`L[559,1050,509]`
- 召回率：胜 **23.2%** / 和 58.9% / 负 **24.0%**（随机 = 33.3%，胜、负两类**低于随机**）
- 平衡准确率 35.38%（随机 33.33%）
- **胜负二分类 AUC（用 P(win)−P(loss) 排序）= 0.4899**（0.5 = 无判别力）；
  真胜样本均分 +0.0030、真负样本均分 +0.0174（方向还略反）
- MSE 0.7686 > 平凡基线 0.4517

→ "正常无塌缩"只是说它没退化成恒猜某一类，但它对**胜负的判断力为零**。
作为 P3 的根节点评估器或价值锚点都不可用。

## 4. 关键发现：p1_v3/test 上的"高分"是评测泄漏

### 4.1 定证（同一模型在不同划分上的对称表现）

| 模型（训练划分） | p1_v3/test 11811 | p1_v2/test 9634 | p1_v2/val 9647 |
|---|---|---|---|
| `bc_best.pt` 2026-09-17（p1_v3/train） | **24.90%**〔未见〕 | **48.86%**〔见过〕 | **45.00%**〔见过〕 |
| `bc_best_legacy_36ch_20260906.pt`（p1_v2/train） | **52.41%**〔见过〕 | **24.39%**〔未见〕 | **24.10%**〔未见〕 |
| `models/best.pt`（策略头=上一个模型） | **52.90%**〔见过〕 | 24.23% | 24.00% |
| `models/pool/bc_best.pt` 2026-09-05（p1_v1/train） | 88.18% | 86.60% | 88.96% |

〔见过/未见〕= 该模型训练划分与本评测划分的对局是否重叠。
**每个模型在"自己没训过的划分"上都只有 ~24–25%，在"自己训过的划分"上跳到 45–52%（更高覆盖率的 p1_v1 模型到 88%）。**
除"训练局混进评测集"外没有别的解释。

### 4.2 机理

- 语料是同一批 1072 个 `.sav`；`p1_v2` 有效 835 局，`p1_v3` 有效 **951 局**
  （原先被判为"损坏/步法非法"的 116 局被重新纳入，`invalid_games=0`）。
- 两版都用 `seed=2026` 洗牌，但洗的是**不同长度的列表** ⇒ 划分完全不同；
  一个版本的 train 覆盖语料 ~80% ⇒ **旧版本的 train 会覆盖新版本 test 的约 80% 局**。
- `metadata.json` 只存 SHA-256 与局数，**不存每个 split 的文件名清单** ⇒ 重叠无法被审计发现。

### 4.3 连带影响（需要一并作废/重测）

1. `reports/eval_bc_best.md`：52.90% / 74.61% —— 泄漏值，不能作为 `best.pt` 的能力证据。
2. `reports/eval_bc_distilled20k_*.md`、`eval_bc_T20_anchor05_tac30.md`：这些蒸馏模型以被泄漏的
   `best.pt` 策略头热启动，40.82% 之类的数字不可信，需在无重叠的 test 上重测。
3. `junqi/train_rl.py:1280-1282` 的注释依据"**实测平衡准确率 0.735 / MAE 0.288**"决定优先取
   `value_distilled_v2.pt` —— 这两个数是泄漏值（在 p1_v3/test 上测得，而该模型训于 p1_v2）。
   该模型**诚实**的数字是它自己的 p1_v2/val：平衡准确率 **0.4467**、MAE **0.9366**。
   也就是说，这个决策是拿**泄漏值**去比 `value_distilled.pt` 的**诚实值**（0.318 / 0.599）。
4. 项目长期记忆与 `docs/CHANGELOG.md` 中引用 0.735/0.288、52.90%、74.61% 的段落需要标注更正。

## 6. 建议的下一步

**先补 P2 的缺口（成本很低，1 天量级）**

1. 跑 P2 验收第 3 条：
   `run.bat gate --a hybrid2 --b search2 --seeds 100 --init-set eval_sets/endgame.jsonl --model-a models/bc_best.pt`
   （配 `--init-set` 是必需的：纯随机发牌下自对局 100% 循环判和，无分辨力。）
2. 用 `games/*.json` 统计送旗/无意义循环比例，补 P2 验收第 4 条。

**修数据切分（这是本次复核暴露出的真正系统性缺陷）**

3. 在 `metadata.json` 里落盘每个 split 的 `.sav` 文件名清单；新增一个
   `scripts/audit_dataset_leakage.py`：对新旧版本两两求 test 交集并断言之。
4. 冻结一份 canonical `test` 集，之后所有版本重新导出时**排除 test 局**，再重测所有候选
   （`best.pt` / `bc_best.pt` / `search_distilled_*`），刷新 CHANGELOG 与长期记忆里的数字。

**再谈 P3**

5. 现在直接 `train_rl` 的热启动会取 21:56 重建的 `models/value_distilled_v2.pt`
   （base = 新 `bc_best.pt`，p1_dir = `datasets/p1_v3`，诚实 val 平衡准确率 **0.3247 < 1/3 随机**、
   MAE 0.710，比 legacy 的 0.4467 更差）。要么改回 legacy 权重，要么接受"价值头从零学"，
   并把 P3 第一轮的期望设为"验证闭环 + Value 健康度恢复"，而不是"变强"。
6. 起点规模按方案：≥300 局/轮、sims ≥ 20、先 3–5 轮；每轮看
   **gate 的"对 `search2` 得分率 + 终局原因拆分 + Value 健康探针"**，禁止只看 loss。

**不要做的事**

7. 不要为了把 Top-1 抬上去继续加 epoch。曲线显示第 4 轮之后 val 只会更差；
   若确实想提升，方向是正则化 / 更小网络 / 更多对局 / 教师软标签（方案 §6 已规定），
   而不是延长训练。
8. 不要在任何"含旧版本训练局"的划分上做晋级对比（包括 `models/best.pt` 作为对手的对比，
   它的策略头本来就来自 p1_v2/train）。
